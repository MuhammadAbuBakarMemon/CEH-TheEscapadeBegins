Parameter Tampering 

applied to websites in which we can pass parameters 
mostly on ecommerce websites 

basically it is commonly used to alter prices on websites through which purchases can be made

Server side requests to be restricted/enforced by the developers to mitigate the vulnurability raised from Parameter Tampering

Session Replay and Session Hijacking

Session is maintained when we open a particular website in our browser
Session Token is generated for each session generated when we open a particular webite on our browser
Token remains intact till the user is using the website 
Once we release the token is when we stop using the website for our particular use

Session Token should get expired after every 15 minutes this is the best practice to be followed 
if the session doesnot expire within 15 minutes and has the expiry of a lifetime then it can lead to these 2 vulnurabilities of 
1) Session Replay 
2) Session Hijacking 

Session Replay
in this we can only login with the userid whose response we have for any particular login request 
whilst 
Session Hijacking 
in this we can login with the userid of anyone who is availabe on the website as a user

Directory Traversal / Directory Browsing 
such hidden directories through which we can obtain access to confidential/sensitive information

Dirbuster or ZAP (also used as a vulnurability scanner tool) is used to obtain the path of directories which might show us sensitive/confidential information 

ZAP gives us the option to perform automated scanning it uses all methods e.g spider etc...
but in a corporate enviornment we do not run the automated scanning all at once because this consumes most of the bandwidth 
and makes the network very slow for all employees to acess therefore we deploy each type of attack one by one
